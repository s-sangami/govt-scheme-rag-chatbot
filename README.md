# 🏛️ Government Scheme Eligibility Chatbot

A RAG-based AI chatbot that allows Indian citizens to upload official government scheme PDFs and ask questions in English, Hindi, Tamil, Telugu, Kannada, or Malayalam. Answers are generated by an LLM from the passages retrieved from that PDF, with the PDF page numbers shown as sources.

---

## 🎯 Problem Statement

Millions of Indians are unaware of government welfare schemes they qualify for. Official documents are long, complex, and written in legal language that most citizens cannot easily understand. This chatbot bridges that gap — making scheme information accessible to everyone in their own language.

---

## 🚀 Features

- 📄 Upload one text-based scheme PDF at a time (uploading a new one resets the session)
- 🌐 Ask questions in 6 languages — English, Hindi, Tamil, Telugu, Kannada, Malayalam
- 🎯 Answers are generated from the 5 most similar chunks of the uploaded PDF; the prompt tells the model to answer only from that context and to say so when the answer is not there
- 📑 Each answer shows the PDF pages its chunks came from ("Sources: page 2, 10")
- ⚡ In-memory FAISS vector search; the index lives only in your Streamlit session and is not written to disk
- 🧪 A small evaluation script (`eval/run_eval.py`) with 10 PM-KISAN questions

The prompt reduces, but does not eliminate, wrong or made-up answers. Small LLMs can still misread or over-generalise the retrieved text, and translation can change meaning. Check important details (eligibility, amounts, dates) against the source pages shown under each answer.

---

## ⚠️ Limitations

- **No OCR.** Text is read with PyMuPDF, so scanned/image-only PDFs produce little or no text and will not work.
- **English-only embeddings, translation in and out.** The embedding model (`all-MiniLM-L6-v2`) is English-only. Non-English questions are detected with `langdetect`, translated to English with Google Translate (via `deep-translator`, needs internet), answered, and translated back. If translation fails, the app shows a notice and falls back to the original/English text. Retrieval and answers are only as good as the translation, and the PDF itself should be in English.
- **Chat history is shown but not used as context.** Earlier messages are displayed in the UI, but every question is answered independently; follow-ups like "and what about the second one?" will not work.
- **One document per session.** There is no multi-PDF upload or switching between PDFs.
- **Retrieval is simple.** Fixed 500-character chunks, top 5 results, no re-ranking, so answers that depend on content spread across many pages can be incomplete.
- **Needs a Groq API key** and internet access (LLM and translation are remote calls).

## 🧠 How It Works

```
PDF Upload
    ↓
Text Extraction per page (PyMuPDF)
    ↓
Text Chunking (LangChain), page number kept as metadata
    ↓
Embeddings (Sentence Transformers)
    ↓
In-memory FAISS Vector Store (per Streamlit session)

User Types Question (any language)
    ↓
Translate to English (Deep Translator)
    ↓
Semantic Search in FAISS
    ↓
Top 5 Relevant Chunks Retrieved
    ↓
gpt-oss-20b Generates Answer from those chunks
    ↓
Translate Answer Back to User Language
    ↓
Answer + "Sources: page X, Y" Displayed
```

## 🛠️ Tech Stack

| Component | Technology | Purpose |
|---|---|---|
| PDF Extraction | PyMuPDF (fitz) | Extract raw text from PDF |
| Text Chunking | LangChain RecursiveCharacterTextSplitter | Split text into 500-char chunks |
| Embeddings | Sentence Transformers (all-MiniLM-L6-v2) | Convert text to 384-dim vectors |
| Vector Store | FAISS | In-memory vector search |
| LLM | openai/gpt-oss-20b via Groq API | Generate final answers |
| Translation | Deep Translator + LangDetect | Multilingual support |
| UI | Streamlit | Web interface |
| Language | Python 3.11 | Core language |

## ⚙️ Installation & Setup

**Step 1 — Clone the repository**
```bash
git clone https://github.com/YOURUSERNAME/govt-scheme-rag-chatbot
cd govt-scheme-rag-chatbot
```

**Step 2 — Create virtual environment**
```bash
python -m venv .venv
.venv\Scripts\activate
```

**Step 3 — Install dependencies**
```bash
pip install -r requirements.txt
```

**Step 4 — Set up your Groq API key**

Create a `.env` file in the project root:
```
GROQ_API_KEY=your_groq_api_key_here
# optional: override the model (default: openai/gpt-oss-20b)
# GROQ_MODEL=openai/gpt-oss-20b
```

The Groq model name can be changed through the `GROQ_MODEL` environment variable; if unset, `openai/gpt-oss-20b` is used.

Get your free API key at: https://console.groq.com

**Step 5 — Run the app**
```bash
streamlit run app.py
```

Open your browser at `http://localhost:8501`

## 🧪 Evaluation

```bash
python eval/run_eval.py
```

Builds the index from `sample_pdfs/pm_kisan.pdf`, asks the 10 questions in `eval/questions.json` in English (translation is not exercised), and prints a pass/fail table. A question passes when the answer contains every expected key fact (any one of the accepted spellings per fact). This is a quick regression check, not a full quality measure: it does not test other PDFs, other languages, or answer wording. Requires `GROQ_API_KEY`.

## 🧪 Key Concepts Used

- **RAG (Retrieval Augmented Generation)** — combines document retrieval with LLM generation
- **Semantic Search** — finds relevant chunks by meaning, not just keyword matching
- **Vector Embeddings** — converts text to numerical vectors capturing semantic meaning
- **FAISS** — Facebook AI Similarity Search for fast local vector retrieval
- **Prompt Engineering** — constrains LLM to answer only from document context
- **Multilingual NLP** — language detection and neural machine translation
